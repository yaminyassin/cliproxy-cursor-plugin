# internal/cursorpb

Generated Go Connect-RPC client types for Cursor's `agent.v1` protobuf
schema (`agent.v1.AgentService` and 4 sibling services: `ControlService`,
`ExecService`, `PrivateWorkerBridgeExternalService`, `LifecycleService`).

## Source of truth

Cursor does not publish a `.proto` schema. The schema is recovered from
`../gajae-code/packages/ai/src/providers/cursor/gen/agent_pb.ts`, which is
itself generated by `protoc-gen-es` and embeds the complete, lossless
`FileDescriptorProto` for `agent.proto` as a compiled binary blob (not
hand-shaped TypeScript interfaces to reverse-engineer).

## Regenerating

```sh
make generate
```

This runs `scripts/extract-cursor-proto/extract.ts` (a Bun script) which:

1. Imports `file_agent` from the sibling `../gajae-code` checkout and
   reads its underlying `FileDescriptorProto`.
2. Renames the small set of top-level messages whose name collides with
   `protoc-gen-go`'s independently-derived oneof-case wrapper struct name
   (see "Known schema quirk" below). Renaming is name-only — no field
   numbers, wire types, or JSON field names change, so this preserves
   full wire compatibility with the real Cursor backend.
3. Serializes the (patched) descriptor to a binary `FileDescriptorSet`
   at `internal/cursorpb/proto/agent.protoset`.

Then `protoc` reads that `.protoset` directly via `--descriptor_set_in`
(no `.proto` text file is required) and runs `protoc-gen-go` +
`protoc-gen-connect-go` to produce:

- `internal/cursorpb/gen/agent.pb.go` — message types.
- `internal/cursorpb/gen/genconnect/agent.connect.go` — typed Connect-RPC
  clients (`AgentServiceClient`, etc.).

Both are committed to the repo so plugin consumers don't need `buf`,
`protoc`, or a `../gajae-code` checkout to build the plugin — only to
regenerate it when Cursor's schema changes upstream.

### Requirements to run `make generate`

- The sibling `../gajae-code` repo checked out (source of the descriptor).
- `bun` (runs the extraction script).
- `protoc`, `protoc-gen-go`, `protoc-gen-connect-go` on `PATH`.

`scripts/extract-cursor-proto/find-collisions.ts` is a standalone
diagnostic that re-scans the descriptor for oneof-wrapper naming
collisions independently of `extract.ts`'s own rename pass — useful for
sanity-checking after an upstream schema update.

## Known schema quirk: oneof wrapper name collisions

Cursor's schema declares some "nested" messages via flat top-level
naming (e.g. `ExaFetchRequestResponse_Approved` as a sibling message of
`ExaFetchRequestResponse`, referenced from a `oneof` field named
`approved`). `protoc-gen-go` independently derives an oneof-case wrapper
struct name from `<Parent>_<CapitalizedFieldName>` — which is the exact
same name for these cases — so the generated Go redeclares the same type
twice and fails to compile.

`extract.ts` resolves this by renaming the colliding top-level messages
with a `Msg` suffix (e.g. `ExaFetchRequestResponse_ApprovedMsg`) before
codegen. This is purely a Go-identifier disambiguation; it does not
change the wire format, so the generated client still round-trips
correctly against the real `api2.cursor.sh` backend.
